# Inside Inkling: where can a decision model stop?

Architecture study, 21 November 2026. **Start with the variable-loop sibling of Inkling 2 Mini on one DGX Spark.** It can process the same input with the same weights at different depths. Pair that with a readout at the exact point where the model predicts an answer. This gives us two separately testable ways to save work on classification and bounded structured output. [Research model card](https://thinkingmachines.ai/model-card/tml-d24-varloop-research/)

There is already a result to explain. In the lab’s original-Inkling runs, restricting the first output to a letter lost 14 previously correct answers out of 28 and gained zero. We reproduced how its template serializes those answers. The letter occupies the **second** position after the generation prompt. The template traces across five checkpoints and the observed answer counts are reproducible with the Sparks off. The gains from moving the readout or changing depth still need a hardware experiment. ## From input to the first answer

**Original Inkling and Inkling-Small.** Text enters through token embeddings. Images enter through a four-layer hierarchical patch encoder with 40-pixel spatial patches. For audio the frontend quantizes 80 mel bands to 16 levels per band, embeds the bands and sums them into frame representations. The resulting media vectors occupy positions in the same causal decoder sequence as text. The image and audio frontends give us separable components for modality-specific experiments. Text-only requests already bypass their computation. Removing the decoder would also remove the component that reads the text and relates it to the media. [Implementation guide](https://huggingface.co/blog/thinkingmachines-inkling) · [First-generation forward pass](https://github.com/huggingface/transformers/blob/4d9ef623e3b0a1fb6c12891a907e0e50d41f0af8/src/transformers/models/inkling/modeling_inkling.py)

Five local-attention layers with a 512-token window precede each global layer. The original has 64 query heads with 16 local or 8 global key/value heads. Small uses 32 query heads with 8 key/value heads throughout. Both use head dimension 128, learned relative-position scores and short convolutions. The first two layers use dense feed-forwards. Later layers select six routed experts per token and include two shared experts, with sigmoid weights normalized over the selected and shared experts together. Ordinary residual addition carries information forward. The final state is scaled before the vocabulary projection, by a divisor of 24 on original and 16 on Small. Their auxiliary eight-layer multi-token predictors can accelerate longer generation. They add little opportunity when the product needs a single terminal decision. [Original model](https://thinkingmachines.ai/model-card/inkling/) · [Small model](https://thinkingmachines.ai/model-card/inkling-small/) · [Router and output implementation](https://github.com/huggingface/transformers/blob/4d9ef623e3b0a1fb6c12891a907e0e50d41f0af8/src/transformers/models/inkling/modeling_inkling.py)

**Inkling 2 Small.** A 23-layer vision transformer, width 1,024 with 16 heads, processes 20-pixel patches. A merger groups 2 × 2 neighboring patches and projects them into the decoder, giving one language-model position per 40 × 40 image area on an aligned grid. This checkpoint takes text and images. The text stack increases the local window to 1,024, uses 48 query and 8 key/value heads, and routes every layer through eight experts with no shared expert. The SwiGLU expert caps its gate and up activations at 4 and 25. Attention uses clipped queries and keys, normalized values, learned relative scores, a learned attention sink and a sigmoid output gate. Global layers apply input-dependent short convolutions to keys and values. These operations matter when porting a fast path that claims to preserve scores. [Generation-two implementation](https://github.com/huggingface/transformers/blob/4d9ef623e3b0a1fb6c12891a907e0e50d41f0af8/src/transformers/models/inkling2/modeling_inkling2.py) · [Publisher release](https://thinkingmachines.ai/news/inkling-2-small/)

The other consequential change is how layers read earlier work. Inkling 2 Small groups 48 layers into eight blocks of six. Outputs accumulate within a block. Learned queries mix earlier block summaries and the current partial block at each token, with distinct reads for global attention’s queries, keys and values. The final read mixes across depth before normalization and the vocabulary head, whose logits have a soft cap of 30. A probe attached to an arbitrary intermediate residual therefore sees a different representation from the one on which the final classifier was trained. Its optional five-layer DSpark drafter taps target positions 5, 11, 17, 23, 29, 35, 41 and 48. Those taps give practical candidate locations for measuring when a decision becomes recoverable. [Checkpoint configuration](https://huggingface.co/thinkingmachines/Inkling-2-Small/blob/4d564489295e30e9341a9822a8046f0c9ded1a7b/config.json) · [Block and final read implementation](https://github.com/huggingface/transformers/blob/4d9ef623e3b0a1fb6c12891a907e0e50d41f0af8/src/transformers/models/inkling2/modeling_inkling2.py)

## Mini exposes the depth experiment

Both Minis have **six opening layers → twelve shared middle layers × P passes → six closing layers**. Each pass starts from the opening block’s output. From the second pass onward, each middle layer also reads two summaries produced by the previous pass. Separate learned reads supply its query, key, value and feed-forward inputs. A rank-64 gate combines each message with its current input. Each extra pass adds 12 layer visits and 48 message reads. The closing block runs once on the final pass’s output. This gives a trained way to reduce depth while retaining both the beginning and the end of the model. [Backend authors’ loop diagram and equations](https://vllm-project.github.io/2026/11/20/inkling2-mini.html)

Production Mini fixes P at three. Its research sibling shares early training, then sampled one through five passes during midtraining with relative frequencies 1, 2, 6, 2 and 1, and used three during post-training. Compare pass counts **within the research checkpoint** to isolate depth. Keep production Mini as an independent reference. Both use native NVFP4 for most expert layers, MXFP8 for the final four, and BF16 elsewhere. The publisher already pruned the expert pool from 384 to 128 and used a trillion-token distillation stage to recover quality. Varying trained depth is the cleaner first intervention than pruning more experts. [Training account](https://thinkingmachines.ai/news/inkling-2-mini/) · [Variable-loop training and supported hardware](https://thinkingmachines.ai/model-card/tml-d24-varloop-research/)

| Passes | Logical layer visits | Local / global visits | Ideal BF16 KV for 8,192 input tokens |
| ---: | ---: | ---: | ---: |
| 1 | 24 | 20 / 4 | 208 MiB |
| 2 | 36 | 30 / 6 | 312 MiB |
| 3 | 48 | 40 / 8 | 416 MiB |
| 5 | 72 | 60 / 12 | 624 MiB |

The cache calculation uses 4,096 bytes per retained token per visit (K and V, eight heads, 128 components, BF16), a 1,024-token sliding window, and independent cache state for each visit and one sequence. Engine page rounding, convolution state, temporary activations and weights cost extra. It is a useful memory bound for a cache that evicts expired local positions. Halving layer visits gives a workload reduction whose wall time depends on actual kernels and prompt length. vLLM sets the research model’s pass count at startup. Its optional shared KV mode changes which pass’s keys and values later tokens see, and the convolution state stays per pass. Leave that option off when testing depth. Mini’s three-layer DSpark drafter uses fixed taps at 5, 23, 41 and 48, so the published implementation requires three passes when drafting. ## What the archived answers reveal

We paired both request modes by question ID and checked the subject, expected answer, prompt hash and reported input-token count. Each launch saw the same 28 ten-choice questions. Ordinary chat streamed up to 16 sampled tokens. The grammar request allowed one letter A–J and a one-token budget. These are two serving protocols, with a shared question and different output settings. [Harness](../../inference-recipes/mmlu_probe.py) · [Archive](../../inference-recipes/results/inkling-mistral-four-spark-2026-11-20/)

| Original Inkling Q3_K_M launch | Ordinary correct | Forced correct | Ordinary alone correct | Forced alone correct | Forced answers |
| --- | ---: | ---: | ---: | ---: | --- |
| Unified FP16 KV | 18/28 | 4/28 | 14 | 0 | 22 G, 6 B |
| Separate slots, Q8 keys | 17/28 | 5/28 | 12 | 0 | 22 G, 5 B, 1 F |

Only three gold answers were G. Every ordinary completion reported four tokens and stopped. Every forced completion reported one token and hit its limit. On the numeric-zero effort fixture the pinned native tokenizer and template reproduced the Spark’s rendered prompt byte for byte. Its last token is the assistant-message marker (200001). A complete answer “H” appends **200004, 39, 200010, 200006** (text marker, H, end of message, end of sampling). All ten letters have this same four-token shape. This is a template replay. The archive retained visible answers and usage, so the sampled token IDs in the original runs remain unknown. One explanation is that the grammar asked for a letter where ordinary chat selects a content type. A token-level trace on the original engine can falsify that explanation. [Archived rendered prompts](../../inference-recipes/experiments/inkling-original/template-check.json) · [Reproduce all ten suffixes](trace.py) · [Publisher rendering documentation](https://tinker-docs.thinkingmachines.ai/cookbook/inkling/tml-renderers/)

The same CPU replay exposes a generation difference that changes the experiment. On the same fixture the first-generation templates put the assistant marker at the end of the generation prompt. All three second-generation templates end the prompt at the preceding message boundary. A completed assistant answer adds **both** the assistant marker and the text marker before its letter. We reproduced all 50 checkpoint/letter combinations. A wrapper that moves one token forward on every Inkling would still read too early for generation two. A serving engine may add its own markers, so log the exact input IDs it evaluates. The native chat interface expects complete assistant messages. Use a local token-level forward pass for the teacher-forced control. ## Smallest change that could pay off

Production Mini’s target SafeTensors header indexes 1,244 tensors and **19,525,870,752 bytes** excluding its separate drafter. Its vision branch accounts for 636,512,256 bytes (3.26%). Its separate input embedding and output head each occupy **926,318,592 bytes**. The BF16 output head has 201,024 rows of width 2,304. For ten known one-token labels, just **46,080 bytes (45 KiB)** of output rows define the candidate scores. This is a weight-byte calculation for the last projection. The decoder still has to read and process the prompt. Ordinary single-token inference also obtains its first prediction from that prompt pass. A measured gain could come from projecting fewer rows, avoiding protocol or JSON generation steps, or reducing depth. Time each independently. [Pinned weight index](https://huggingface.co/thinkingmachines/Inkling-2-Mini/blob/ed40e7da625f594fc9c4990f5f66be24873c22d7/model.safetensors.index.json) · [Header inventory](audit.py)

At the same hidden state, a dot product with each selected row yields the corresponding vocabulary scores. Preserve the model’s final normalization, scaling, soft cap, precision and tie policy. Verify per-label logits and argmax against the ordinary full projection restricted to those IDs. Probabilities normalized over the ten labels are conditional on that set. Calibrate them against actual correctness. Multi-token labels require scoring their full continuations, including shared prefixes, or fitting a dedicated class head. For a fair sequence comparison, specify the termination rule and how lengths are scored. A deterministic serializer can turn one selected outcome into valid JSON. Dependent fields need joint or conditional decisions, and free-form values need extraction or generation.

## First one-Spark study

FastBERT trained intermediate classifiers, CALM calibrated early exits, and Huginn tested adaptive compute in a recurrent language model. Thinking Machines already evaluated its own research checkpoint at different depths with the start of the answer prefilled. A publishable contribution here would quantify when a model-specific answer readout and a decision to continue from the first pass preserve accuracy on unseen schemas, including what an escalation actually costs on a Spark. [FastBERT](https://aclanthology.org/2020.acl-main.537/) · [CALM](https://arxiv.org/abs/2207.07061) · [Huginn](https://arxiv.org/abs/2502.05171) · [Inkling 2 Mini experiments](https://thinkingmachines.ai/news/inkling-2-mini/)

1. **Find the answer position.** With native chat, record rendered token IDs, the first few sampled IDs and their logits, visible text and completion reason. Compare ordinary chat, the original first-token constraint, and candidate scoring after a verified text marker. Include matched greedy requests, reasoning effort, budgets and streaming settings to isolate the changes. Verify the row-only readout against full-vocabulary masking at the identical position. Repeat with shuffled answer order and shuffled label-to-class mappings. A persistent G bias after these controls would weaken the template explanation.
2. **Measure how much depth the decision uses.** Run the research checkpoint at fixed P = 1, 2 and 3 on the same Spark, in its native precision, with separate per-pass KV and drafting disabled. Compare each at the same answer boundary. Use production Mini’s native chat as an external baseline. Include ticket routing, document status, deliberately missing information, and linked lookups of increasing depth. The publisher already found that additional passes particularly helped chained lookups. The interesting question is whether we can identify which requests need them. [Publisher’s no-chain-of-thought experiments](https://thinkingmachines.ai/news/inkling-2-mini/)
3. **Fit a decision to continue.** First test a calibrated margin between the top two one-pass labels. On ambiguous requests, run three passes and include the entire fallback cost. With two independent prefills and roughly uniform costs, the mean-latency break-even fallback fraction is below `1 − T₁/T₃`. Measure per-request costs for real traffic. A second experiment can train a small probe on the first middle pass’s summaries and continue from retained prompt states before running the closing layers. First verify those shared states against an uninterrupted three-pass reference across all input positions. Producing a single terminal output permits this experiment without having to reconcile earlier generated tokens at different depths. Compare the margin gate with escalation at random at the same rate, simple prompt-length routing and an oracle that knows which depth was correct on each held-out item. These controls separate a useful confidence signal from the benefit of extra computation alone. [Mini engine constraints](https://vllm-project.github.io/2026/11/20/inkling2-mini.html)
4. **Make the outcome publishable either way.** Separate fitting, calibration and held-out data by document or template family. Include unseen templates, longer prompts, ambiguous cases and abstentions. Publish semantic exact match and per-class errors separately from schema validity, agreement with three passes, calibration, coverage and fallback fraction. At one and four clients, measure end-to-end p50/p95 time to the complete decision, decisions/s and GPU joules per decision, including fallbacks. Use wall-meter totals if available and label the energy source. Report cold and warm prompt behavior, repeated launches, and paired confidence intervals. A proposed success threshold is an upper 95% confidence bound of one percentage point on extra decision error against the full-depth baseline and at least a 25% reduction in p95 latency or joules/decision. Choose the endpoint and size the held-out panel before running it. The existing 28 examples are a diagnostic.

For image-only decisions, a later experiment could fit a classifier directly to pooled vision features for a bounded task such as document type, then send uncertain images and text-dependent questions through the decoder. This would genuinely bypass the decoder on accepted cases. It requires labeled images, a vision-only baseline and a test set where visible text or fine spatial detail changes the answer. For text decisions, the template replay and the supported one-Spark depth control give us a shorter route to a decisive result.

## Reproduce the offline findings

From the repository root, the first command uses the standard library to read five pinned configs, the Mini target tensor index, only the SafeTensors header, and the archived Spark decisions. The second renders ten completed answers with each checkpoint’s pinned template and tokenizer and checks the original prompt against the recorded Spark fixture. Both run on a CPU. For the paired decisions with no network, use `python3 research/inkling/audit.py --archive-only`.

```sh
python3 research/inkling/audit.py
uv run --script research/inkling/trace.py
```
