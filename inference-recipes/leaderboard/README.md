# Open-weight inference queue

The November 19, 2026 snapshot contains 44 releases with a current Artificial Analysis Intelligence Index score. The queue retains the highest-scoring effort setting per release and sorts by its unrounded score. A leaderboard result belongs to the provider configuration named in the row. The Spark experiments use their own prompts, reasoning settings and metrics. The [checkpoint inventory](weights-2026-11-19.csv) covers all 44 ranked releases. Each row links an immutable Hub revision. Sizes sum the root SafeTensors files, including auxiliary or draft files in the root. The count omits duplicate consolidated copies where the conventional weight files are also present. Model variants such as Xiaomi's RL and MOPD are listed separately because the leaderboard label alone does not identify the locally downloaded variant.

The planning column picks the smallest of one, two or four Sparks allowing 110 GiB per node for weight files. Each lab Spark reports about 121 GiB total. The allowance is a consistent way to triage downloads. An engine may repack, replicate or offload tensors, and individual ranks may have different memory demands. Runtime support, KV cache, working memory, interconnect and a successful completion determine actual serving fit. Ranks 2, 3 and 8 have published serving configurations whose checkpoint layout or compression changes the required hardware.

The November 20 GGUF inventory verifies the architecture string in each first-shard header and sums the complete text model’s individual shard sizes at a pinned revision. It excludes optional vision, audio and draft heads. Each row carries its candidate node count and source manifest. [GGUF inventory](gguf-2026-11-20.csv)

On one Spark the lab built llama.cpp at `6aee50801d091f78b3baacd505f5e95d8e8f6838` for ARM64 and SM121a. We fetched the beginning of every shard over HTTP ranges, extended each staged file sparsely to its manifest size, and checked that its entire GGUF header was present. The allocation-free model load then checked named tensor shapes across all shards. Five conversions passed and two original Inkling conversions reached an unsupported architecture. These checks cover metadata only. GPU allocation, decoding and answer quality require the actual weights. [Per-conversion results](gguf-loader-2026-11-20.csv) · [Probe source](gguf_loader_probe.cpp) · [Engine revision](https://github.com/ggml-org/llama.cpp/tree/6aee50801d091f78b3baacd505f5e95d8e8f6838)

To repeat against a local shared-library build, compile the probe with `c++ -std=c++17 -I "$src/include" -I "$src/ggml/include" gguf_loader_probe.cpp -L "$lib" -lllama -lggml -lggml-base -o probe`. Set `LD_LIBRARY_PATH` to include the build's library directory. Run `./probe header SHARD PREFIX_BYTES` for each staged shard, then `./probe model FIRST_SHARD`. The lab fetched up to 16 MiB of each first or standalone file and 256 KiB of each subsequent shard. Retain the original shard names together in one directory.

Refresh the scores with `python3 snapshot.py > YYYY-MM-DD.csv`. Use the linked manifests to recheck byte counts at the recorded checkpoints. Record successful configurations and measured limitations alongside the [inference results](../results/).
